# 被其他 skill 调用：派发并守护

其他 skill（以下称**调用方**）的流程里有一步是「把某个阶段交给另一个 pane 的 agent 做」时，直接调用本 skill 完成派发和守护，**不要把派发、等待、回调的步骤写进调用方**。本 skill 不知道调用方是谁，只按调用方给的参数办事。

`<skill 目录>` 指本 skill 的 `SKILL.md` 所在目录的绝对路径。

## 1. 分工

| | 调用方 | 本 skill |
| --- | --- | --- |
| 提供 | 已向用户确认过的分工（执行者 kind、谁是调度者）、提示词、回调句、被回调后的处理 | 选执行者 pane、派发、确认开始、额度守护、回调、`ticket` 与 `plan` |
| 不做 | 不自己 `herdr agent prompt` 派发，不写回调或等待脚本，不另起 watcher | 不读、不改调用方的状态文件，不知道调用方的阶段 |
| 判断「做完没有」 | 读自己的状态文件 | 只判断「执行者稳定停下且不是额度原因」 |

调用方的分工配置（例如它的阶段分工表）视为用户已经指定了执行者和调度者，满足本 skill「分工必须明确」的硬规则；调用方没有给出执行者 kind 或任务内容时，停下询问，不猜测。

## 2. 调用步骤（调度者侧）

1. **前置检查和选择执行者 pane**：按 [dispatch.md](dispatch.md) 第 1–2 节（调用方引用它，不复制）。其中先运行 `start-watcher.sh whoami` 取得调度者自己的权威 pane、工作区、tab（Codex 里环境变量可能过期，它会自动发现），后面的 `$HERDR_PANE_ID`、`--scheduler` 的值，以及调用方写进自己状态文件的「调度者 pane」，都用它的输出，不要直接用环境变量。执行者永远是另一个 pane，只在调度者所在的工作区内选；脚本会拒绝把调度者自己或当前 pane 当作执行者（退出码 2，不发送）。
2. **一条命令派发并启动 watcher**：

   ```bash
   sh '<skill 目录>/scripts/start-watcher.sh' dispatch \
     --executor <执行者 pane> --scheduler "<whoami 的 pane_id>" --scheduler-kind <调度者 kind> \
     --prompt '<调用方给执行者的提示词>' \
     --callback-on stop \
     --callback-prompt '<回调时发给调度者的一行文本，例如：使用 $<调用方> 继续调度（任务：<任务标识>）'
   ```

   - `--callback-on stop`：提示词原文照发，只在后面追加一句让执行者创建完成标志的话，不追加「写结果文件」的样板；执行者稳定停在 `idle`/`done` 且不是额度原因时，watcher 回调调度者。适合执行者靠调用方自己的状态文件交接的流程。
   - `--callback-prompt`：调度者收到的就是这句话，所以要带上调用方定位任务所需的标识；不能以 `-` 开头，最长 500 字符。
   - 长提示词用 `--prompt-file <文件>` 代替 `--prompt`。
   - **完成标志由本 skill 指定，调用方不必也不能指定文件路径**：脚本在 `<标志目录>/<任务ID>.done` 生成新路径（每次派发都是新文件，不会出现「文件已存在」），`stop` 模式下自动在提示词后追加一句「完成后的最后一步：创建空文件 <路径>」；执行者创建它，watcher 看到就立即回调。没有标志时要等一个观察期（`QW_STOP_GRACE`，缺省 60 秒）才回调，因为 herdr 对某些 agent 会在运行中短暂报 `idle`/`done`，不能据此认定执行者已完成。
   - **`--marker-dir <绝对路径>`（可选）**：标志所在的目录。缺省是执行者工作目录下的 `.herdr-scheduling-tmp`（单独调用时就是项目路径下的临时文件夹）；有自己工作区目录的调用方可以指到它下面的临时文件夹（例如 `<项目根>/AGENT_WorkSpace/.herdr-tmp`）。目录不存在时由脚本创建。
   - **清理**：回调发出后 watcher 删除本次的标志，目录是脚本创建且已空时一并删除；异常结束时保留，**调用方在整个流程结束后检查并删除残留的标志目录**。
   - 命令的全部选项和退出码见 dispatch.md 第 3 节。
3. **按退出码处理**：

   | 退出码 | 调用方怎么做 |
   | --- | --- |
   | 0 | 记录派发（任务目录、`watcher_pane`），向用户报告，结束本轮 |
   | 3 | 不在 herdr 中，或无法确定调度者自己的 pane：`HERDR_PANE_ID` 无效或不在当前工作区，Codex 里还可能是共享 app-server 守护进程带来的旧值，且自动发现没有唯一匹配。说明原因，按提示处理（用 `codex --no-daemon` 启动，或由用户给出真实值）后重试，不要用手填的 pane ID 继续 |
| 8 | 执行者被阻塞（在等批准或回答）：不启动 watcher；读它最多 40 行交给用户，不要自己批准 |
   | 9 | 没有确认开始：提示词可能已送达，不要重发；`agent read` 看一眼屏幕再报告用户 |
   | 5、7 | **提示词已送达、执行者在工作，但 watcher 没有启动**：报告用户，说明没有额度保护；排除问题后用 `run <任务目录>` 补启动 |
   | 2、4 | 参数或执行者问题：按错误信息修正或报告用户 |

4. **结束本轮**，进入空闲，不等待、不轮询。

## 3. 被回调唤醒后

调度者收到 `--callback-prompt` 给的那句话，**由调用方接手**：读调用方自己的状态文件，判断执行者是做完、停在待确认，还是遇到阻塞，再按调用方的流程处理。不读执行者的完整输出，也不要按 dispatch.md 第 5 节处理（那是缺省回调句的流程）。

`--callback-on stop` 意味着「执行者停下」就会回调，所以**回调不等于完成**：执行者可能在中途向用户提问后停在 `idle`。调用方必须以自己的状态文件为准。

## 4. 执行者中途的几种情况

| 情况 | watcher 的行为 |
| --- | --- |
| 触达额度限制 | 等到恢复时间，向同一个会话发条件式「继续」，最多重试 3 次；恢复后执行者继续做完，再回调 |
| 停在 `blocked`（等批准或回答，屏幕没有额度文案） | 通知用户一次，**继续守护**；用户处理后执行者回到 `working`，watcher 接着等它停下。最多等 `QW_BLOCK_MAX`（缺省 2 小时），超时通知用户并结束，保留 pane |
| 稳定停下（`idle`/`done`）但没有完成标志（`stop` 模式） | 先观察 `QW_STOP_GRACE`（缺省 60 秒）：标志出现 → 立即回调；回到工作状态 → 继续守护；到期仍停着 → **同时**通知用户（「执行者已停下，但没有完成标志」，常见原因是中途提问）并回调调度者，之后继续守护，执行者恢复工作并做完后再回调一次 |
| 停在 `unknown` 等不明状态 | 通知用户并异常结束，保留 pane，**不回调** |
| 恢复失败、重试用尽、恢复时间超过 24 小时等 | 通知用户并异常结束，保留 pane，**不回调** |

后两种情况不会回调调度者：调度者靠 herdr 通知（用户看到后处理）或用户手动唤醒。需要重新守护时运行 `start-watcher.sh run <任务目录>`。

## 5. 调用方应避免的事

- 不要在调用方里再写一份「等执行者完成并回调」的脚本或步骤；回调只由 watcher 发送，执行者不需要也不应自己回调。
- 不要给 `--callback-prompt` 写不含任务标识的句子：同一个调度者可能同时有多个任务的回调。
- 不要把「稳定停下」当作「已完成」：`stop` 模式的回调只表示执行者停下了（可能是提问）。以调用方自己的状态文件为准；执行者在结束前创建本 skill 指定的完成标志，才是确定的完成信号。
- 不要把调用方的状态写进本 skill 的任务目录（`${TMPDIR:-/tmp}/herdr-scheduling/<任务ID>/`），那里只放 `ticket`、`plan`、`prompt.txt`、结果和 `done`。
