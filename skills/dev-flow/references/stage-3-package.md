# 阶段 3：任务包

## 目标

把一份已确认技术方案**整份、原样、可追溯**地转换成开发任务包。任务包只包含两个文件：

```text
<任务目录>/开发任务包/1-任务声明.md
<任务目录>/开发任务包/2-技术方案小节片段.md
```

不得在 `开发任务包/` 下创建方法名或模块名子目录。一份技术方案生成一个任务包；现有任务包不得被静默替换。

## 使用条件

- 技术方案位于 `AGENT_WorkSpace/<任务>/技术方案.md`，状态已确认。
- 开发须知中存在指向该方案的唯一任务条目，状态至少为「设计已确认、待开发」。
- 项目、代码根、方案或任务条目无法唯一对应时停止。

## 边界

- 只生成上述两个文件，并更新开发须知中该任务的状态和任务包链接。
- 不生成 `实施与静态检查记录.md` 或其模板（由开发执行阶段生成）。
- 不修改技术方案、`AGENTS.md`、`CLAUDE.md` 或代码；不评审、不提交。
- 不修改开发须知中的当前功能、算法、接口、代码基线或验证结论。
- 不用源码、历史任务包、开发须知或常识补写方案没有的设计、自检或允许修改范围。

## 工作流

### 1. 加载

1. 读取项目根和代码根适用的全部 `AGENTS.md`。
2. 完整读取开发须知，核对项目根、代码根、代码基线和任务条目；条目缺失、仍为「方案待确认」、链接指向其他方案或映射不一致时停止，不静默补登记。
3. 完整读取 `技术方案.md`（不能只读搜索命中附近几行）；核对方案状态已确认，记录开发须知哈希相对方案记录值是否变化。

### 2. 定位整份方案

有效定位同时满足：路径唯一；首个 Markdown 标题可识别为方案标题；摘录从该标题首字符开始到文件最后一个字节结束；方案与开发须知条目都表明已确认；方法清单来自实际的方法级详细设计标题。

- 标题前的 YAML frontmatter、HTML 注释或说明会影响状态、范围或追溯时，一并纳入并在定位中说明。
- 方法清单只收集承担实质详细设计的标题中的精确方法名；接口表、调用图、文件清单、验收矩阵中的提及不计入。没有方法级小节时写「方案未定义方法级小节」，不从源码补造。标题层级或编号冲突导致清单不唯一时停止询问。
- 核对需求、总体设计、数据结构、方法级设计、修改范围、禁止修改、必须保留、自检/验收等章节是否存在；缺失只记录，不补造。

写文件前先输出定位，等待用户确认，确认前不创建 `开发任务包/`：

```text
技术方案：<绝对路径>
方案标题：<首个 Markdown 标题>
方案状态：<已确认状态>
摘录范围：从方案首个标题开始，到文档结束
纳入方法：<按方案顺序列出；无则写“方案未定义方法级小节”>
```

herdr 调度例外：`调度方式：herdr`，且路径唯一、状态已确认、方法清单唯一、第 3 步未发现矛盾时，把定位写入「待确认事项」并标「自动通过（herdr 调度）」后继续；任一条件不满足仍停止。

### 3. 处理方案矛盾

摘录前检查整份方案内部是否存在会改变实现的矛盾，例如：需求、总体流程和方法设计对同一动作给出不同顺序或次数；数据结构与方法读写字段不一致；方法允许的行为被全局禁止项禁止；同一超时、返回值、次数或参数映射在不同章节不一致；验收依赖方案禁止或未定义的实现。措辞详略不同但语义兼容不算矛盾。

发现矛盾立即停止，列出冲突章节、原文含义和影响；用户确认口径后才生成，并在片段文件头写注记：

```text
> 注：原技术方案第 X 节与第 Y 节对某项内容描述不一致；经用户确认，本任务包采用……。
```

不反向修改原方案；后续评审必须能看到该注记。

### 4. 生成 2-技术方案小节片段.md

用 [../assets/2-技术方案小节片段模板.md](../assets/2-技术方案小节片段模板.md)：文件头记录方案路径、摘录范围、纳入方法、方案 SHA-256、开发须知 SHA-256、摘录完整性说明（只描述缺失）；正文从方案首个标题原样摘录到文件结束，保持标题层级、段落、表格、代码块和数值。生成后把摘录正文与来源逐字节比较，换行、空格、标点变化都算不一致。

### 5. 生成 1-任务声明.md

用 [../assets/1-任务声明模板.md](../assets/1-任务声明模板.md)，只填三部分：

1. **方案**：任务名、方案标题/路径/哈希/状态、摘录范围、纳入方法、项目根、代码根、版本控制、开发须知路径/哈希、代码基线。
2. **范围**：按完整方案汇总默认允许修改、条件允许修改、方案明确依赖、禁止修改和必须保留；依赖只采用方案明确给出的关系，不因名称相似扩大范围。
3. **自检**：只采用方案明确要求的检查和验收；缺失时标「方案未规定」，不新增虚构标准。

初始状态固定为「待开发工程师确认」。

### 6. 输出

1. `1-任务声明.md` 或 `2-技术方案小节片段.md` 已存在时停止询问，不静默覆盖。
2. 写入两个文件，不创建其他文件或子目录。
3. 写入并通过完整性检查后，开发须知任务条目改为「任务包已生成、待开发」并加两个文件的相对链接；不把方案内容写入当前实现区。
4. 报告文件路径、方案标题与哈希、纳入方法、缺失项、矛盾注记。

## 写入任务状态

- 等待定位确认、矛盾口径确认或是否覆盖现有任务包：`阶段状态：待用户确认`，问题写入「待确认事项」后停止。
- 完成：「产物」登记两个文件；写 `当前阶段：开发执行`、`阶段状态：待执行`、`下一步：开发执行（首次实施）`。
- 任务条目缺失、方案未确认等前置不满足：`阶段状态：阻塞` 并说明原因。
