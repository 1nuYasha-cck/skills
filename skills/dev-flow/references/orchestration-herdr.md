# 调度模式 —— 通过 herdr 让其他 agent 执行下一步

当前 agent 作为**调度者**时使用。派发、确认对方已开始、额度中断后的自动恢复和回调由 `herdr-scheduling` skill 负责；本文只规定 dev-flow 自己的部分：分工、状态、何时派发下一阶段、被回调后怎么办。herdr 命令语法和安全规则以已安装的官方 `herdr` skill 为准。调度者不做阻塞等待：派发后结束本轮，由回调唤醒，避免调度者（尤其是 Codex）在等待期间反复被唤醒消耗额度。

## 前提

- `test "${HERDR_ENV:-}" = 1`；不满足即说明不在 herdr 中并停止。
- 已安装 `herdr-scheduling`，且版本包含调用接口：能读到它的 `references/integration.md`，并且其中说明了 `--marker-dir`（完成标志目录）和 `whoami`（取得调度者自己的权威 pane）。未安装，或已安装但版本过旧（读不到该文件，或没有这两项），都说明原因，请用户安装或更新 `herdr-scheduling`，然后停止；**不自己拼 herdr 命令派发**。

## 触发

- 单步：「通过 herdr 让 codex 执行下一步」「让同工作区的 claude 做代码评审」。
- 全流程：给出分工，如「开发执行由 claude，其余由 codex，调度由 herdr 负责」。

## 被派发 agent 收到的提示词

dev-flow 给出的部分固定为一句，不附加背景、摘要或上下文：

```text
使用 $dev-flow 完成下一步动作：<阶段>（任务：<任务目录名>）
```

附任务目录名，是因为同一项目可能有多个未完成任务。被派发 agent 所需的全部信息都从 `任务状态.md` 和项目文件读取。

herdr-scheduling 会在这句之后追加一句让执行者创建**完成标志**的话（调度标志，不是阶段工作）；被派发 agent 在本次运行结束、`任务状态.md` 已写好之后照做，见 `SKILL.md` 第 8 步。

## 派发时传给 herdr-scheduling 的参数

| 参数 | 值 |
| --- | --- |
| 执行者 kind | 「阶段分工」里该阶段指定的 agent kind |
| 提示词 | 上面的一句 |
| 工作目录 | 项目根：执行者的 cwd 必须等于项目根（被派发 agent 靠当前目录定位项目，提示词里只有任务目录名） |
| 回调方式 | 执行者停下就回调（`--callback-on stop`）：执行者靠 `任务状态.md` 交接，不写结果文件 |
| 回调句 | `使用 $dev-flow 继续调度（任务：<任务目录名>）`（`--callback-prompt`） |
| 完成标志目录 | `<任务目录>/.herdr-tmp`（任务目录的绝对路径，即 `<项目根>/AGENT_WorkSpace/<任务目录名>/.herdr-tmp`；`--marker-dir`）。标志文件由 herdr-scheduling 生成，每次派发都是新文件，不会已存在 |
| 调度者 | 本 agent 的 kind 和 `whoami` 输出的 `pane_id`（Codex 里环境变量 `$HERDR_PANE_ID` 可能是过期的旧值，不要直接用） |

具体命令、选项和退出码处理见 herdr-scheduling 的 `references/integration.md` 第 2 节。执行者永远是另一个 pane（即使与调度者同 kind），由 herdr-scheduling 校验。

## 回调契约

回调只表示「执行者停下了」，**不等于阶段完成**；调度者被回调后一律以 `任务状态.md` 为准（流程第 6 步）。watcher 在其他情形下是否回调、做什么，见 herdr-scheduling 的 `references/integration.md` 第 4 节，此处不重复。被派发 agent 在本次运行结束时创建完成标志，回调随即发出；没有创建时 herdr-scheduling 会先观察再回调（细节见其 `integration.md`，此处不重复）。被派发 agent **不自己回调**，写好 `任务状态.md` 后结束本轮即可。

## 流程

1. **环境检查**：满足「前提」两项，否则停止。
2. **定位任务**：按 `SKILL.md` 第 1–3 步确定项目和任务；任务不唯一时先问用户。
3. **写入调度信息**：把用户给出的分工写入「阶段分工」，并写 `调度方式：herdr`、`调度者：<本 agent kind>（<whoami 的 pane_id>）`、`调度模式：单步|全流程`、`调度起始评审轮次：<当前评审轮次>`。未指定的阶段由调度者自己执行。
4. **选下一阶段**：读 `任务状态.md`：
   - `待执行` → 该阶段可派发；
   - `待用户确认` / `阻塞`，且该阶段的待确认事项已全部标 `已确认` → 可派发（执行者按 SKILL.md 第 5 步继续）；
   - `待用户确认` / `阻塞`，仍有未确认事项 → 不派发，转第 7 步；
   - `完成` → 报告任务已完成，并删除 `<任务目录>/.herdr-tmp`（若存在；`rm -r`，只删这个目录）：每次回调后 herdr-scheduling 已删除自己的标志，这一步只清理异常结束留下的残留。
5. **派发（或本会话执行）**：
   - 该阶段**未指定 agent** → 直接在本会话按 `SKILL.md` 执行该阶段，然后回到第 4 步。
   - 该阶段**指定了 agent**（即使与调度者同 kind）→ 使用 `$herdr-scheduling`，按其调用接口派发，参数见上表；选执行者按 herdr-scheduling 的规则（只在当前工作区内，不新建 workspace / tab / worktree）。
   - 选定的 `pane_id` 记入 `任务状态.md`「阶段分工」表该阶段的 agent 列（如 `codex（wF:p1）`），后续阶段优先复用；复用前仍按 herdr-scheduling 的选择规则复核，不满足条件（例如正忙）就重新选，不对忙碌的 agent 插话。
   - 命令成功（退出码 0）：在 `任务状态.md` 写 `派发记录`（阶段 → pane，时间），向用户报告「已派发 <阶段> 给 <pane>，完成后它会回调」，然后结束本轮，进入空闲；不 `agent read` / `agent get` 轮询。
   - 其他退出码按 integration.md 第 2 节处理，不重试、不盲目重发；退出码 5、7 时执行者已在工作，同样写 `派发记录`，并在报告中说明这次没有额度保护。
6. **被回调唤醒后**：收到「使用 $dev-flow 继续调度（任务：<任务目录名>）」时，读 `任务状态.md`（以它为准，不读对方完整输出）：
   - 状态已按预期推进 → 转第 7 步。
   - 状态与派发前相同或不符合预期 → 读对方 pane 最多 80 行确认原因，报告用户，不重复派发。
7. **决定继续或停止**：
   - `调度模式：单步` → 报告本阶段结果与下一步后结束。
   - `调度模式：全流程`：新阶段为 `待执行`（或待确认事项已全部确认）→ 回到第 4 步；`待用户确认` / `阻塞` → 把「待确认事项」中未确认的问题原样转述给用户并停止。
   - 修复循环上限：`评审轮次` − `调度起始评审轮次` ≥ 3 且仍为「开发执行（修复）」时停止报告。
8. **用户答复后**：调度者把用户原话写入对应待确认事项并标 `已确认`（技术方案确认、提交确认必须来自用户明确答复），然后回到第 4 步，仍只发送标准提示词。
9. **手动唤醒**：没有收到回调（含 watcher 已退出）时，用户可直接对调度者说「使用 $dev-flow 继续调度」，按第 6 步处理。

## 规则

- 技术方案确认、提交确认在调度模式下也是必停门禁；调度者不得代替用户确认。
- 调度者不执行被派发阶段的工作，也不修改阶段产物，只写调度信息（分工、调度方式、调度者、调度模式、调度起始评审轮次、派发记录）和用户确认记录。
- 调度标志目录 `<任务目录>/.herdr-tmp` 是临时文件，只在任务 `完成` 时由调度者清理；其间不计入改动边界、不评审、不提交。
- 调度者和被派发 agent 都不做阻塞等待；回调由 herdr-scheduling 的 watcher 发送，被派发 agent 不自己回调。
- 调度范围限定在调度者所在的 herdr 工作区（`$HERDR_WORKSPACE_ID`）。
- 一次只派发一个阶段；阶段之间严格串行，不并行派发同一任务的不同阶段。
