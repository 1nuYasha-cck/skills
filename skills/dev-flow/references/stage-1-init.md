# 阶段 1：项目初始化

## 目标

让项目具备 dev-flow 运行所需的两份文件：

```text
<项目根>/AGENTS.md                    # 项目信息与稳定规则；已存在则只读
<项目根>/AGENT_WorkSpace/开发须知.md   # 当前实现、进度、重要改动索引
```

`AGENTS.md` 只保存稳定规则，`开发须知.md` 保存当前实现、技术逻辑、进度和重要改动。代码服从规则，不能用当前实现反向改写规则。

## 使用条件

- 项目根按 SKILL.md「目录约定」确定。当前目录只是子模块、文档子目录或源码内部目录时，不自动上升或下降到候选根，请用户确认。
- 用于首次初始化，或用户明确要求重建、校正开发须知。

## 边界

- 只创建缺失的 `AGENTS.md` 和 `开发须知.md`；不生成 `CLAUDE.md`（Claude Code 可直接读取 `AGENTS.md`）；不修改业务代码、工程配置、需求资料或生成文件。
- 已存在的 `AGENTS.md` 只读，不修改；发现其中与 dev-flow 相关的信息冲突或不唯一时，报告并询问。
- 已存在的 `开发须知.md` 不覆盖；用户要求重建时先展示拟修改范围并等待确认。
- 不创建任务目录、技术方案、任务包、实施记录、评审报告或 `任务状态.md`。
- 不评审、不提交、不推送，不运行会改变外部状态的命令。

## 工作流

### 1. 读取适用规则

1. 读取项目根到当前目录适用的全部 `AGENTS.md` 及其引用的规则文件。
2. 按 SKILL.md「项目信息来源」确定代码根：AGENTS.md 声明了就用声明的路径，否则为项目根。声明的路径不存在或指向多个候选时停止，零写入。
3. 代码根独立于项目根时，读取代码根到工程目录适用的 `AGENTS.md`。
4. 盘点需求、资料、架构说明、构建文件、源码目录和已有开发记录。

### 2. 分类事实

- **固定规则**：项目范围、权威路径、固定配置和参数、索引映射、禁止项、验证边界 → `AGENTS.md`。
- **动态实现**：当前功能、算法、接口、进度、待验证事项 → `开发须知.md`。
- **计划需求**：尚未实现的需求 → 只在开发须知中写为待开发目标。
- **未知或冲突**：显式保留为「待确认」，不补造。

不写入 `AGENTS.md` 的内容：函数/类/接口的当前数量和清单、源码行号、当前 Commit 和进度、会随需求正常变化的算法步骤、某次检查或运行的结果、只为兼容当前错误实现而加的规则。

### 3. 缺少 AGENTS.md 时生成

用 [../assets/AGENTS模板.md](../assets/AGENTS模板.md)，只写有文件证据支持的内容：

- 适用范围和资料索引；
- 代码位置：只有代码不在项目根时才写；
- 技术栈、构建入口、检查命令：有证据（构建文件、脚本、说明文档）才写；
- 验证边界：哪些验证必须在目标环境完成；
- 专项结构和禁止修改项：有证据才写。

无法证实的项写「待确认」，不推测语言、框架、硬件或部署方式。删掉不适用的章节和模板提示语。

### 4. 生成开发须知

在 `<项目根>/AGENT_WorkSpace/开发须知.md` 用 [../assets/开发须知模板.md](../assets/开发须知模板.md) 生成当前基线，区分已实现、计划开发和未验证。代码根是 git 仓库时，代码基线写当前 `HEAD` SHA；否则写「非 git，基线以任务快照为准」。不写函数数量、源码行号或未经证明的运行结论。

### 5. 检查与报告

1. 检查新写文件中的路径、Markdown 链接和模板占位符。
2. 报告：生成了哪些文件、代码根及其来源（AGENTS.md 声明 / 缺省为项目根）、版本控制状态、未决问题。
3. 本次生成了 `AGENTS.md` 时，在报告开头明确告知：「已根据项目内容生成 AGENTS.md，请审阅；标为待确认的项需要你补充。」

## 写入任务状态

- 本阶段没有任务目录，不创建 `任务状态.md`。
- 停止时直接向用户报告，不写任何文件。
- 完成后报告：初始化完成；下一步为「技术方案」，需要用户提出需求并要求设计方案。
