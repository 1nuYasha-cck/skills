# 阶段 2：技术方案

## 目标

把用户需求、项目资料、`开发须知.md` 和当前代码整理成一份可执行、可追溯、能拆分方法级任务包的 `技术方案.md`，区分正式要求、源码事实、设计推断和未验证事项，并在开发须知中登记方案状态。

## 使用条件

- 项目已初始化（`AGENTS.md`、`AGENT_WorkSpace/开发须知.md` 都在）；否则停止，提示先完成阶段 1。
- 项目根、代码根不唯一时停止。

## 边界

- 只创建任务目录、`技术方案.md`、`任务状态.md`，并更新开发须知中该任务的状态与链接。
- 不生成任务包、不改代码、不评审、不提交。
- 不修改 `AGENTS.md`，不改写开发须知中的当前实现、算法或验证结论。
- 不把静态分析表述为构建、运行、集成或设备验证证据。
- 不用历史记忆、文件名相似度或旧任务包替代当前项目文件和当前源码。

## 工作流

### 1. 确定项目、代码根和规则

1. 读取项目根到当前目录适用的全部 `AGENTS.md` 及其引用的、与任务相关的规则文件。
2. 按 SKILL.md「项目信息来源」确定代码根，读取代码根适用的 `AGENTS.md`。
3. 执行版本控制判定：`git -C <代码根> rev-parse --show-toplevel`，结果写入状态文件。
4. 在方案中列出本次实际读取的规则文件、代码根及其来源、版本控制状态。
5. 规则、开发须知和源码对权威路径、允许范围或验证方式存在无法解释的冲突 → 停止报告，不静默修正。
6. 方案必须修改代码但代码根缺失、候选不唯一或需求模块在工程中不存在 → 停止，不创建空任务目录。

### 2. 读取权威输入

1. 完整读取 `开发须知.md`，记录路径、SHA-256、当前状态和代码基线。它是当前实现摘要和任务索引，不能替代权威资料和当前源码；发现过时先报告影响，会改变核心设计时停止。
2. 读取用户需求原文及最新补充。
3. 读取与任务相关的项目资料和源码；需要时使用格式专用工具或技能。
4. 定位维护源码、生成文件、配置和调用入口，区分各自角色。
5. 对关键来源记录路径、版本或哈希。
6. 资料缺失标为待确认；缺失内容会改变核心设计时先停下询问。

### 3. 证据分类

方案中的结论必须能归入以下一类：

1. 用户明确要求（本次对话的最新明确指令）；
2. 项目正式要求（当前需求、协议、规范等资料）；
3. 当前源码事实；
4. 设计决策（说明理由和影响）；
5. 待确认推断（不得作为已确认要求下发）；
6. 未验证事项（需要构建、运行、集成或目标环境才能证明）。

历史方案和旧任务包只帮助定位，不高于当前需求、规则和源码。

### 4. 编写方案

可采用 [../assets/技术方案模板.md](../assets/技术方案模板.md)，删除不适用部分和提示语。要求：

- 需求拆成目标、非目标、必须保留行为、禁止修改项和验收边界。
- 说明当前实现、问题位置、调用关系和受影响文件；给出总体流程、状态变化、数据结构、接口和错误路径。
- **方法级详细设计**：每个实际需要开发的方法有独立标题，标题含源码中的精确符号名，编号层级一致（如 `8.3 ExampleMethod`）；小节范围从该标题到下一个同级方法标题之前。接口表、调用图、文件清单中的提及不算方法级设计。只写有依据的内容，不为凑模板虚构。
- **修改范围**：默认允许修改、条件允许修改、禁止修改、必须保留的行为、生成文件与维护源码边界。
- **验证边界**：按证据等级（文本/结构检查、静态语法、本地构建、目标环境构建、运行、集成、目标设备或生产环境）只列项目实际适用的级别；未执行的写「未执行 / 待验证」，不能用低等级代替高等级。
- 未实现的设计只能写在方案里，不能提前写进开发须知的当前实现区。

### 5. 创建输出

1. 在 `AGENT_WorkSpace/` 下新建能表达需求的任务目录；同名目录已存在时停止询问，不覆盖、不合并。
2. 写入 `技术方案.md`（文档状态「待用户确认、未实施」）和 `任务状态.md`。

### 6. 更新开发须知

1. 在「重要改动索引」新增或更新唯一任务条目：任务名、技术方案相对链接、影响模块、状态「方案待确认」。
2. 用户确认方案后，只把条目状态改为「设计已确认、待开发」。
3. 开发须知已有同名任务但指向不同方案、代码根或项目时停止询问。

### 7. 输出前检查

- 每条用户需求在方案中有对应位置；需求、设计、修改点和自检可相互追踪。
- 方法级小节标题含精确方法名且唯一。
- 关键数值、字段和映射都有来源或标为设计决策。
- 允许修改、禁止修改、必须保留和验证边界明确。
- 没有把旧文件、生成代码或历史记录当成当前基线；没有残留模板占位符。
- 开发须知只新增了任务状态和链接。
- 报告：文件路径、开发须知条目、主要来源、未决问题、未执行验证。

## 写入任务状态

- 新建任务：用 [../assets/任务状态模板.md](../assets/任务状态模板.md) 创建，填写项目根、代码根、版本控制；`当前阶段：技术方案`、`阶段状态：待用户确认`、`下一步：用户确认技术方案`；「待确认事项」登记「确认技术方案」；「产物」登记 `技术方案.md`。
- 技术方案确认是**必停门禁**，手动与 herdr 调度都不得自动通过。
- 用户确认后：开发须知条目改为「设计已确认、待开发」，方案文档状态改为已确认，写 `当前阶段：任务包`、`阶段状态：待执行`、`下一步：任务包`。
- 用户要求修改：在同一任务目录修改方案，仍为「待用户确认」。
- 尚未创建任务目录就停止时，不创建状态文件，直接报告。
