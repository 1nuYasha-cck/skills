# dev-flow 开发流程

## 目标

用一份 `任务状态.md` 把一次需求从方案推进到提交。本 skill 只规定**流程和硬约束**（工作区与任务目录结构、各阶段产物、状态机、确认门禁、证据边界、改动边界）；任何项目信息都不写在 skill 里，运行时从项目 AGENTS.md 读取（见「项目信息来源」）。

| 阶段 | 阶段文档 | 主要产物 |
| --- | --- | --- |
| 1 项目初始化 | [stage-1-init.md](references/stage-1-init.md) | `AGENT_WorkSpace/开发须知.md`；缺失时生成 `AGENTS.md` |
| 2 技术方案 | [stage-2-plan.md](references/stage-2-plan.md) | `<任务目录>/技术方案.md`、`任务状态.md` |
| 3 任务包 | [stage-3-package.md](references/stage-3-package.md) | `开发任务包/1-任务声明.md`、`2-技术方案小节片段.md` |
| 4 开发执行 | [stage-4-execute.md](references/stage-4-execute.md) | 代码修改、`开发任务包/实施与静态检查记录.md` |
| 5 代码评审 | [stage-5-review.md](references/stage-5-review.md) | `<任务目录>/评审报告.md` |
| 6 提交 | [stage-6-commit.md](references/stage-6-commit.md) | git：提交（有上游时推送）；非 git：基线登记 |

状态文件格式、迁移表和确认门禁见 [state-file.md](references/state-file.md)；herdr 调度见 [orchestration-herdr.md](references/orchestration-herdr.md)。

## 目录约定（固定）

```text
<项目根>/
├── AGENTS.md                          # 项目信息与稳定规则（用户维护；缺失时由阶段 1 生成）
└── AGENT_WorkSpace/
    ├── 开发须知.md                     # 当前实现、进度、重要改动索引
    └── <任务名称>/
        ├── 任务状态.md
        ├── 技术方案.md
        ├── 评审报告.md
        ├── 基线快照/                   # 仅代码根不是 git 仓库时
        └── 开发任务包/
            ├── 1-任务声明.md
            ├── 2-技术方案小节片段.md
            └── 实施与静态检查记录.md
```

- 项目根 = 用户给出的路径，否则当前目录。当前目录位于 `AGENT_WorkSpace/<任务>/` 内时，项目根取该 `AGENT_WorkSpace` 的父目录，并视为用户点名了该任务。其他情况不静默上升或下降目录。
- 代码根可以与项目根相同，也可以在项目根之外，由项目 AGENTS.md 声明。

## 项目信息来源

优先级从高到低；仍不唯一时停止询问，不猜测：

1. 用户本次指令；
2. 项目根到当前目录适用的全部 `AGENTS.md`、其中引用的规则文件，以及代码根到工程目录适用的 `AGENTS.md`；
3. 可探测的状态：`git -C <代码根> rev-parse --show-toplevel`、`git rev-parse --abbrev-ref @{u}`、工具链文件（`package.json`、`pyproject.toml`、`go.mod` 等）；
4. 下表缺省值。

dev-flow 用到的信息全部可选；AGENTS.md 按正文读取，不要求固定标题：

| 信息 | 缺省 |
| --- | --- |
| 代码根 | 项目根 |
| 需求 / 资料位置 | 在项目根内盘点 |
| 开发前同步要求 | git：fetch 后只做安全快进；非 git：无 |
| 静态检查 / 构建命令 | 按工具链线索选常见检查（见 stage-4）；无法确定记「未执行」 |
| 目标环境验证边界 | 构建、运行、集成、设备验证一律记「未执行」 |
| 提交约定（说明格式、语言、分支） | 见 stage-6 默认格式；不切换分支 |
| 专项结构、同步和禁止修改约束 | 无 |

项目可以在 AGENTS.md 中加一个 `## dev-flow` 小节，只放精确命令，避免每轮即兴拼命令：

```markdown
## dev-flow

### preflight        （开发执行 Phase 1 的追加步骤，按序执行，任一失败即停）
- <命令或动作>

### static_check     （开发执行 Phase 4 通用检查之外的项目检查）
- <名称>: `<命令>`  (pass_when: exit==0)

### 结构标记          （实施前后计数必须相等的成对标记）
- <标记名>: `<统计命令>`
```

**版本控制判定**：技术方案阶段执行 `git -C <代码根> rev-parse --show-toplevel`，把 `代码根` 和 `版本控制：git（<仓库根>）| 无` 写入 `任务状态.md`；后续阶段沿用并复核，结果变化时停止报告。是否提交只由此决定。

## 协作方式

所有阶段只通过 `任务状态.md` 和项目文件交接，不依赖会话上下文：

| 方式 | 说明 |
| --- | --- |
| 单 agent | 同一个 agent 每次运行推进一个阶段 |
| 多 agent 手动接力 | 不同 agent 或会话轮流执行（如 Codex 写方案、Claude 开发），靠状态文件交接 |
| herdr 调度（可选） | 调度者在同一 herdr 工作区内按「阶段分工」派发，被派发方完成后回调；仅 `HERDR_ENV=1` 时可用 |

## 每次运行的流程

### 1. 检测项目初始化

缺少 `AGENTS.md` 或 `AGENT_WorkSpace/开发须知.md` → 执行阶段 1，本次结束。用户同时提了需求时，报告中说明初始化完成后再运行会进入技术方案。

### 2. 扫描未完成任务

1. 读取 `AGENT_WorkSpace/*/任务状态.md`，收集「当前阶段」不是 `完成` 的任务。
2. 与 `开发须知.md`「重要改动索引」交叉核对：索引中有未完成条目但没有状态文件的任务，列为「待补登记」，不自动创建状态文件。

### 3. 决定本次动作

- **用户提出新需求并要求设计方案**：存在未完成任务时，先列出（任务名、当前阶段、阶段状态）并询问「继续已有任务」还是「仍新建」；没有未完成任务或用户确认新建 → 执行阶段 2。任务目录只在这里创建。
- **用户点名任务**（名称、路径或位于任务目录内）→ 使用该任务。
- **未提新需求**（「完成下一步动作」「继续」等）→ 未完成任务唯一则继续；多个则列出询问；没有则提示用户先提出需求。
- **调度请求**（提到 herdr、让某个 agent 执行、给出阶段分工）或**回调**（「使用 $dev-flow 继续调度（任务：…）」）→ 按 orchestration-herdr.md 执行。

### 4. 读取状态

读取任务的 `任务状态.md`，得到当前阶段、阶段状态、待确认事项、代码根、版本控制、阶段分工和调度方式。

- 请求中点名的阶段与状态文件不一致 → 停止报告。
- 状态文件与开发须知或实际产物冲突 → 停止报告，不静默修正。
- 用户请求修复但状态不在开发执行：状态为 `代码评审 / 待执行` 时先说明并询问；状态为 `完成` 时询问是否以修复模式重新打开（确认后写 `开发执行 / 待执行`，下一步 `开发执行（修复）`）。

### 5. 处理确认

阶段状态为 `待用户确认` 时，只有对应待确认事项已标 `已确认`，或用户本次消息明确给出确认，才继续；用户本次给出确认时，先把原话写入该事项并标 `已确认`。否则复述未确认事项后停止。

### 6. 执行阶段

用 Read 完整读取对应阶段文档并按其执行。阶段文档中的边界、停止条件、禁止项和格式要求全部生效；本文件不放宽其中任何一条，只有 state-file.md「确认门禁」表列出的 herdr 调度例外。

### 7. 写入状态

阶段结束或停止时，按阶段文档末尾「写入任务状态」和 state-file.md 更新 `任务状态.md`。

### 8. 回调调度者

`调度方式：herdr` 且 `调度者` 不是自己（`$HERDR_PANE_ID`）时，写完状态后按 orchestration-herdr.md「回调」唤醒调度者，不等待其响应。阶段完成、停在待确认或阻塞都要回调。

### 9. 报告

简短报告：本阶段结果（区分静态检查与真实构建/运行）、产物路径、下一步，以及按「阶段分工」应由哪个 agent 执行下一步。

## 全局硬约束

- 一次运行只执行一个阶段（herdr 调度由调度者串行推进多个阶段）。
- 技术方案确认、提交确认（git 时）在任何模式下都必须由用户确认。
- 除阶段 6 外，所有阶段都不提交、不推送。
- 只修改授权文件；与本任务无关的已有改动全程不读、不写、不提交。
- 不 force push、不改写历史、不 reset / stash / clean、不切换分支、不自动 merge / rebase。
- 未获授权不部署、不启动真实服务或设备、不发送真实请求或报文。
- 证据分级：静态检查不能证明构建、运行、集成或设备验证通过；没执行的写「未执行」，绝不写成 PASS。
- 路径、项目根、代码根、任务、方案或差异基线不唯一时停止询问。
- 规则服从于项目：本 skill 与项目 AGENTS.md 冲突时，按更严格的一方执行；无法判断时停止询问。
- 被 herdr 派发时，提示词只有一句「使用 $dev-flow 完成下一步动作：<阶段>（任务：<任务目录名>）」；所需信息全部从 `任务状态.md` 和项目文件读取。
- 计算哈希统一用 SHA-256（`shasum -a 256` 或 `sha256sum`）。
