# 测试设计方法

Agent 根据用户要求和需求语义选择方法，脚本不生成用例。

- 边界值：列出每个参数的上下界、单位、包含关系、离散精度；设计边界点和相邻合法/非法点。缺少精度、公差或阈值时询问或注明，不自行选择。
- 等价类：列有效与无效输入类，每类明确依据、代表值及预期；涉及多输入时判断交互风险，不把单参数覆盖当作组合覆盖。
- 判定表：整理条件、规则组合、动作及不可达组合的依据，覆盖项对应规则列。
- 状态迁移：整理初态、事件、守卫、目标状态、动作和非法迁移，设计事件顺序与历史。
- MC/DC：从原文识别每个判定和原子条件，构建 and/or/not 树。对每个条件找两条观察：该条件翻转、其余条件相同、结果翻转。同一环境/历史条件必须一致；在 observations 中用 context 记录。不可达组合和耦合条件导致未覆盖时解释原因，不省略条件以声称 100%。
- 错误推测、性能、网络、HIL 等按用户给定模型使用开放覆盖项；不补造协议或设备参数。

覆盖项必须绑定需求编号并在用例中引用；每个 MC/DC observation 必须绑定实际用例编号及其需求。计算结果只证明提供模型中的设计覆盖，不能证明需求模型完整或测试通过。
