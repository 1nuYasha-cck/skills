# Agent 检查要点

## 输入与读取

先确认来源、设计方法（开放取值）、目标比例、模板和输出。来源未指定就询问，不扫描用户设备。对本地来源只读，记录 SHA-256、版本（可以缺失）、需求原文与 Sheet/坐标/段落定位。受支持的格式按魔数识别，HTML 伪装的 XLSX 仍按 HTML 读取。PDF、旧 XLS、图片等未读取成功需转换或补充来源。

## 理解、复用与设计

Agent 从原文整理完整需求清单，不补造信号阈值、时间、公差、设备条件或版本。缺少判据则列待确认项。按用户设计方法建立覆盖项和判定模型。Search 可选：核对链接原文与适用条件，分别记录直接复用、改写、新写及理由，不能因为功能相似就认为可直接复用。

每条用例绑定需求、方法和覆盖项，写明前置条件、步骤及对应预期。修订时先明确用户授权范围、旧用例与新用例的对应关系，执行结果不转换成预期，不删除非目标内容。模板中旧执行字段需要 Agent 明确映射和保留。

## 核算与交付

核算分母来自提供的需求和覆盖模型；脚本不证明模型完整。MC/DC 必须唯一原因独立影响对，不能用 masking 替代；相关环境和历史不同的观察不能配对。观察是设计用例的逻辑取值，不能冒充设备实测。未达目标时补齐设计或说明无法达成原因。

Agent 读取模板结构，确定映射；生成后核对所有用例、长文本、合并、步骤顺序、非目标 Sheet、样式与公式。不把文件可加载当作视觉检查通过。交付来源清单、用例文件、cases.json、覆盖报告、复用说明及未执行验证。

上传需明确目标文件夹，先审查草稿内容及 dry-run。上传后文件列表确认 token，云文档全文回读；这只证明当前上传样本可读取，不代表入库或设备验收。失败保留已完成 token 与错误，不自动重试结果未知的写入。交 Maintain 的文件是普通文档，由 Maintain Agent 再次理解和审核。
