# lark-testcase-maintain

把手头已有的测试用例文档整理后导入飞书测试用例库（多维表格 + 云文档），并做日常维护。

## 解决什么问题

- **用例文档格式五花八门**：不同项目、不同人写的用例，表头、列顺序、合并单元格、分组标题、统计行、报告混在一起，固定模板或脚本很难可靠识别。本 skill 让当前 agent 阅读原文、判断哪些是用例、怎么分类、字段怎么归属；脚本只负责读出带位置的原文和写飞书。
- **入库不规范、无法追溯**：脚本统一完成上传原件、写分类目录、写用例记录、生成分类正文云文档、登记导入批次，并在写入后回读核对，每条用例都能追溯到原文件和原位置。

## 前提

- 已安装并登录飞书命令行工具 `lark-cli`，当前用户对目标多维表格和云盘文件夹有读写权限。所有调用固定使用用户身份（`--as user`）。
- Python 3.10+；读取 xlsx 需要 `openpyxl`，读取 docx 需要 `python-docx`。

## 标准用例库

一个用例库 = 一个多维表格 + 一个云盘文件夹：

| 部分 | 内容 |
| --- | --- |
| `用例库目录` 表 | 每个分类一行：分类路径、说明、关键词、用例数、正文链接 |
| `测试用例` 表 | 每个用例一行：编号、标题、分类、步骤、预期、需求编号、设计方法、适用版本（可空）、扩展字段、来源文件与位置、审核状态等 |
| `导入批次` 表 | 每次导入一行：来源文件、原件哈希、新增/更新/未变/冲突数、执行结果 |
| 云盘文件夹 | `原件/` 保存上传的原始文件，`正文/` 每个分类一份可读的正文云文档 |

没有库时，可以让 agent 用 `init-library` 新建一个；库的配置文件（含真实 token）保存在你自己的项目里，不放进 skill。

## 已有索引库与维护台账

已有的“正式用例索引 + 正文分卷 + 入库审核台账”可以使用 `schema_profile: "indexed"`，不需要迁移成标准三表库。正式索引与维护台账可以分属不同多维表格：用 `table_base_tokens` 指定各表所在的 Base，用 `field_maps` 适配实际字段名。`config_version` 仍为 `2.0`，未配置新模式时保留标准库行为。

配置样例见 [config.example.json](../skills/lark-testcase-maintain/assets/config.example.json)，完整配置与发布规则见 [索引库说明](../skills/lark-testcase-maintain/references/indexed-library.md)。索引模式要求分类目录、正式索引、来源记录、批次与审核表；问题表、分表路由可选。`init-library` 创建标准库，不负责自动搭建已有索引库的台账。

索引模式把保存与正式发布分开：

1. `import` 归档或复用原件，登记批次，保存“待审核 / 未入库”的审核行。
2. 人工在审核表中确认最新版本，填写审核人和审核时间。
3. `publish` 重新读取审核与完整发布输入，先写并核验正文，再更新正式索引，最后标记审核行已入库。审核后内容、身份或来源被改动会被拒绝，须重新导入并审核。

在已安装的 skill 目录执行发布命令：

```bash
python3 scripts/maintain.py publish --config <配置文件> --library <库名> --out <预演报告> --dry-run
python3 scripts/maintain.py publish --config <配置文件> --library <库名> --out <发布报告>
```

可选发布计划只能选择系统用例ID与备注，不能提供审核结果。预演会读取当前 schema、记录与审核状态，但不会执行远端写入。历史审核行不自动补造新审核绑定；需要修订时重新导入为新版本，再人工审核。

系统用例ID与原编号分离，同一原编号可以对应不同来源的用例，需显式声明允许重复；不会按原编号覆盖。章节标题使用可读编号、标题和内容版本，通过指向唯一索引记录的回链确认身份。修订新增章节，保留旧章节与锚点；按配置的数量和预计字符容量分卷，单条用例不切断。结果未知时只读回确认，核验回链与正文内容后才恢复；已发布而审核台账更新失败时可以重跑补齐。

## 浏览与双向导航

日常浏览视图可显示原编号、标题、分类、版本、状态和正文链接，将长系统ID、哈希、文档 token 等技术字段留在底层数据。`browse-view` 只修改配置指定的浏览视图，不删除字段，也不修改完整字段视图；隐藏字段不等于限制读取权限。

正文中包含“返回用例索引”“返回检索浏览”“返回正文目录”，正式索引指向对应正文章节。租户地址、正文目录和浏览视图来自配置；缺少必要地址时不会猜测链接。浏览入口或目录缺省时会报告缺项。

## 怎么用

对 agent 说明来源文件和目标库，例如：

> 用 lark-testcase-maintain 把 `<用例文档>` 导入到 `<配置文件>` 里的用例库

agent 会按下面的顺序工作：

1. **读取**：用 `doc_extract.py` 把文档读成带位置的文本。按文件内容判断真实格式（扩展名是 xlsx 但实际是 HTML 也能识别），支持 xlsx、docx、csv/tsv、html、md/txt/json；读不了的格式会明确说明，不会假装已读。
2. **理解与整理**（agent 完成）：区分用例、说明、统计和执行记录，逐条整理成标准字段；放不进标准字段的内容原样保存在「扩展字段」；没有版本号就留空，不阻断。
3. **预览**：向你展示分类、条数、样例和存疑项，你确认后再写入。
4. **导入**：先 `--dry-run` 看将新增、更新、跳过哪些用例，再实际执行；写完自动回读核对。
5. **报告**：给出飞书链接、各类计数和回读结果；部分失败会如实标为 `partial`。

同一文件重复导入只处理变化的用例，未变就跳过。标准库直接导入用例表，默认「审核状态=待审核」；索引库先保存到审核台账，人工审核后还需执行 `publish`。

## 维护

- `check`：只读核对编号、必填、分类、正文和人工改动；索引模式还检查章节归属、审核绑定、回链和文档版本，结果交给 agent 判断如何处理。
- `export`：把配置注册的表与正文导出到本地做备份；读取不全会标为 `partial`。
- 废弃用例：在导入计划里把状态改为「已废弃」后重新导入。

## 与其他 skill 的关系

- 可以单独使用，不需要先装 `lark-testcase-search` 或 `lark-testcase-write`。
- `lark-testcase-write` 生成的用例文档就是普通文档，按本流程导入即可；它附带的 `cases.json` 字段与库同名（步骤、需求编号等用数组也能接受），agent 可以直接参考，但仍会复核。

## 边界

- 本地来源文件只读、只上传，不会被修改；输出不能写在来源文件所在目录里。
- 单元测试不能证明真实飞书环境、并发、权限和容量都没问题；未执行的验证会写明未执行。
- 分卷字符容量按 XML 预计长度判断，实际 CLI 的规范化与新增 block ID 开销仍需在目标环境验证。
