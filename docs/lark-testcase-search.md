# lark-testcase-search

在飞书的测试用例库和云文档里查找与需求相关的测试用例，给出库级和用例级的匹配度、差异和复用建议。全程只读。

## 解决什么问题

- **需求描述可能很模糊**：例如“设备被卡住后会不会自动退回”。本 skill 让 agent 把描述展开成多组关键词（同义词、上下位概念、相关功能、典型测试点），多轮召回；精确线索（用例编号、需求编号、信号名）则按编号字段直接查。
- **不止一个库**：用例可能分散在多个多维表格和云文档里，字段也各不相同。脚本把各库的表、字段、分类和记录读全，字段含义由 agent 读字段表后理解，不要求库的结构统一。
- **匹配不等于可复用**：关键词命中只是召回信号。是否真的相关、和需求差在哪、能不能直接用，由 agent 阅读原文后判断，并附上原文引用。

## 前提

- 已安装并登录飞书命令行工具 `lark-cli`，当前用户对要检索的资源有读取权限。所有调用固定使用用户身份（`--as user`）。
- Python 3.10+（只用标准库）。
- 一份检索配置，列出要检索的用例库（多维表格）和云文档文件夹。配置保存在你自己的项目里，格式见 skill 内 `references/config.md`。

## 怎么用

对 agent 说明需求和配置，例如：

> 用 lark-testcase-search 在 `<配置文件>` 里找“电机过热后还能不能继续动作”的相关用例

agent 会：

1. **理解需求**：分开精确线索和模糊描述，展开关键词并说明理由。
2. **库级召回与判断**：`libraries` 读出各库的表、字段、分类目录和用例数，必要时 `doc-search` 搜索飞书云文档；agent 给每个库、分类和文档打出高 / 中 / 低 / 不相关，低匹配也保留在报告里。
3. **用例召回**：`find` 按关键词和字段检索（分页读全）；库较小或召回不足时 `dump` 全表通读；云文档用 `doc-read` 读正文。
4. **用例判断**：逐条给出完全匹配 / 高 / 中 / 低 / 不相关，以及直接复用 / 修改后复用 / 仅参考 / 不建议，附理由、差异和可复核的原文引用；证据不足就写“未判定”。
5. **输出报告**：agent 写 `search_result.json`，`render` 生成 Markdown 报告，写明实际检索了哪些库、表、文档、关键词和字段，是否读全，失败在哪。

## 结果怎么用

- 报告和 `search_result.json` 可以直接交给 `lark-testcase-write` 编写新用例，接收方 agent 会重新复核，不会照搬检索结论。
- 发现库里的数据问题（例如编号重复、正文缺失）只在报告里指出，由你决定是否用 `lark-testcase-maintain` 处理；本 skill 不会写入任何飞书资源。

## 边界

- 检索中途分页失败或权限不足时会保留已读结果并标为不完整，不会把“没读到”说成“没有”。
- 外部库字段超过 20 个时，默认只取按名称排序的前 20 个做初步召回，并列出被省略的字段，agent 必须补查或指定关键字段。
- 本地测试不能证明现场召回质量，也不能代表其他账号的权限。
