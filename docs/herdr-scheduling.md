# herdr-scheduling

在 [herdr](https://herdr.dev) 里把任务派发给另一个 pane 的 coding agent，并在它因额度限制停下时自动恢复。

## 解决什么问题

- **调度者空等**：让一个 agent 去指挥另一个 agent 时，指挥者如果一直等着，会白白消耗额度。本 skill 让调度者派发后只确认对方已开始，随即结束本轮；执行者完成后由后台脚本唤醒调度者。
- **额度中断后没人管**：执行者触发额度限制后会停下，它自己发出的完成通知永远不会到来，调度者一直空闲，你也不知情。本 skill 用一个不消耗模型额度的后台脚本（watcher）识别中断，等到恢复时间后让**同一个会话**继续。

## 前提

- 在 herdr 里运行（环境变量 `HERDR_ENV=1`）。
- 已安装官方 herdr skill（命令语法以它为准）。
- 目前支持的 agent：Claude Code、Codex。

## 怎么用

### 1. 派发：指定调度者和执行者

对当前 agent 明确说明分工，例如：

> 你作为调度者，让 codex 去完成：<任务内容>

- 必须说明**执行者是哪种 agent**，并明确让当前 agent 担任调度者；缺少任何一项，它会停下来问你，而不是猜。
- 调度者和执行者可以是同一种 agent（例如都是 Claude Code），但执行者**总是另一个 pane**，不会在调度者自己的会话里做。
- 调度者派发后立即结束本轮，**不消耗额度等待**。执行者完成后，watcher 会回调唤醒调度者，由它向你报告结果。

### 2. 监视：对已有 pane 单独启动 watcher

> 盯着 <某个 pane>，额度恢复后让它继续

必须指明目标 pane，且它要在当前工作区内。watcher 只负责额度恢复，不派发任务。

### 启动 watcher 的辅助脚本

调度者不需要手工拼命令：skill 自带 `scripts/start-watcher.sh`。派发入口用 `dispatch` 一条命令：建任务目录和派发单、向执行者发提示词并确认它已开始、再拆出专用 pane 启动 watcher（会核对工作区和 tab、确认启动成功），顺序是**先派发并确认执行者已开始，再启动 watcher**；它会拒绝把调度者自己或当前 pane 当作执行者。分步使用时，`init` 只创建任务目录和派发单，`run` 在确认执行者已开始后启动 watcher，`watch` 则是监视入口的一条命令。

### 被其他 skill 调用

其他 skill 的流程里需要「把某个阶段交给另一个 pane 的 agent 并守护」时，可以直接调用本 skill，不必自己写派发和回调：调用方提供提示词和回调时发给调度者的那句话，`start-watcher.sh dispatch` 一条命令完成派发、确认开始和启动 watcher；执行者停下且不是额度原因时，watcher 回调调度者，由调用方读自己的状态文件判断结果；本 skill 会让执行者在结束前最后一步创建一个由它自己指定的完成标志（项目路径下的临时文件夹里，每次派发都是新文件，回调后自动删除），回调在看到标志时立即发出（否则会先观察约一分钟，因为 herdr 对某些 agent 会在运行中短暂报告「已完成」）。执行者中途提问而停下时，会通知你并回调调度者，之后继续守护，回答后执行者做完会再回调一次。额度中断同样自动恢复。接口说明见 skill 里的 `references/integration.md`。

### 静音选项

监视模式下，被守护的 agent 每次正常停下默认都会弹一条通知。如果被守护的 agent 本来就会一个阶段接一个阶段地结束（例如被另一个流程反复调用），可以在启动时加 `--notify-stop 0` 关掉这一种通知。额度相关和所有异常通知不受影响，始终会发出。

### 3. 方案 D：不等待，改派（可选）

默认是等额度恢复后让同一个会话继续。只有你**同时**明确说「额度耗尽时不等待」和「改派到哪种 agent」，才会改派到当前工作区里已有的那个 agent；找不到合适的目标就会停下告诉你，不会悄悄改成等待。

## watcher 做什么

它运行在被守护 agent 所在工作区、同一个标签页里的一个**专用普通 pane**（不是 agent，不消耗模型额度）：

1. 等被守护的 agent 稳定地停下。
2. 已经完成：回调调度者，然后关闭自己的 pane。
3. 因额度限制停下：从报错文案、状态栏、用量命令（Claude 的 `claude -p "/usage"`、Codex 的 `/status`）里得到恢复时间，等到那个时间（Claude 自带自动续跑时多等 5 分钟，其余多等 1 分钟），再向**同一个 pane** 发一句：

   > 额度已恢复。如果上一项任务尚未完成，请从中断处继续；如果已完成，只回复已完成。

   最多重试 3 次。
4. 执行者停在 `blocked`（等你批准或回答）：用 herdr 通知提醒你，**继续守护**；你在执行者的 pane 里处理后，watcher 接着等它做完或处理额度，最多等 2 小时，超时通知你并结束。（监视入口下，`blocked` 仍是通知后结束。）
5. 无法自动处理的情况（提问、被打断、工作区没有额度、恢复时间超过 24 小时、重试用尽等）：用 herdr 通知提醒你，并保留 watcher 的 pane 让你看到原因。

不会因为看到 pane 空闲就盲目发「继续」：恢复前会先判断是不是额度中断、是否已经完成。

## 出问题时

- **watcher 异常退出**：任务目录（`${TMPDIR:-/tmp}/herdr-scheduling/<任务ID>/`）里有 `plan` 记录当前状态。可以在新开的 pane 里重新运行 `quota-watcher.sh --ticket <任务目录>`，也可以直接对调度者说「使用 $herdr-scheduling 继续调度（任务：<任务ID>）」。
- **调度者没有被唤醒**：同上，手动对调度者说那句话即可。

## 已知限制

- 真实额度耗尽下的行为**还没有实测**：额度期间 herdr 对 Claude 标记的状态、Codex 额度耗尽后会话能否输入，以及限额状态下用量命令能否正常工作，都未验证。额度文案来自开源代码和第三方文章，也未在真实限额下验证。
- 恢复时间未知、且屏幕上的旧额度文案一直留着时，watcher 无法判断额度是否已恢复，会每 30 分钟探测一次，最长 12 小时，然后通知你。
- herdr 对某些 agent（实测 Codex）会在运行中短暂把状态报成「已完成」，所以「稳定停下」不等于「已完成」；用完成标志才可靠。
- Codex 的共享后台守护进程如果在更早的 herdr pane 里启动，经它启动的 Codex agent 会继承过期的 `HERDR_PANE_ID` 等环境变量。最稳妥的办法是用 `codex --no-daemon` 启动作为调度者的 Codex（herdr 里启动时在命令末尾加 `-- --no-daemon`）。没有这样启动时，脚本会在发现环境变量过期后自动用 `herdr agent list` 按类型、工作目录和状态找到调度者真实所在的 pane，只在能唯一确定时采用，并告诉你依据；有歧义（例如同目录有多个 Codex）会停下，让你确认真实值。`start-watcher.sh whoami` 可以随时查看它认定的 pane。
- 首版一次只派发一个执行者。
