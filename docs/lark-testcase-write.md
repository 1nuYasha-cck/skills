# lark-testcase-write

根据你指定的需求分析和设计方法要求编写测试用例，核算覆盖率，并按任意模板生成用例文档；可选上传到飞书草稿。

## 解决什么问题

- **按设计方法写用例**：你可以提出“边界值 + 等价类”“需求覆盖 100%”“MC/DC 覆盖 100%”等要求。agent 先按方法建立覆盖模型（边界点、等价类、判定与条件等），再编写用例；脚本按模型核算覆盖率，没达到目标会如实报告缺口和原因，不会缩小分母。
- **复用已有用例**：可以结合 `lark-testcase-search` 的检索结果或你指定的参考用例。agent 逐条复核后决定直接复用、修改后复用或不采用，并写明理由；检索结论只作参考。
- **不同模板生成不同文档**：模板结构由 agent 读出后决定字段放在哪一列、每条用例一行还是每个步骤一行，脚本按映射填写并保留模板样式。同一批用例换一个模板，就得到另一种版式的文档。

## 前提

- Python 3.10+，`pip install -r scripts/requirements.txt`（`openpyxl`、`python-docx`）。
- 只有上传飞书草稿时才需要已安装并登录的 飞书命令行工具 `lark-cli`，调用固定使用用户身份（`--as user`）。

## 怎么用

对 agent 说明需求来源、设计要求和模板，例如：

> 用 lark-testcase-write，按 `<需求分析文件>` 编写测试用例，要求等价类 + 边界值、需求覆盖 100%，用 `<模板文件>`

- **需求来源必须由你指定**（本地文件、飞书链接或直接贴原文）。没有指定时 agent 会先问，不会自己在电脑上找文件。
- 需求里缺的参数（阈值、单位、边界算不算触发等）会列为待确认，不会自行补数值。

agent 会按这个顺序工作：

1. `extract` 读取需求，agent 整理需求条目，标出矛盾和缺失。
2. 可选：结合检索结果复核可复用的用例。
3. agent 建覆盖模型并编写 `cases.json`（字段名与飞书标准用例库一致）。
4. `coverage` 核算需求覆盖、各方法覆盖项和 MC/DC 独立影响对，生成 JSON 和可读的 Markdown 报告。
5. `inspect-template` 读出模板结构，agent 写映射，`fill` 生成新文件（xlsx、docx 或 Markdown）；模板原件不会被修改。
6. agent 打开生成结果核对内容与版式。
7. 你要求时 `upload` 把文件和 Markdown 草稿上传到你指定的云盘文件夹并回读；这是草稿，不是入库。

## 模板

- 内置两个模板：`标准用例表.xlsx`（每条用例一行）和 `步骤展开表.xlsx`（每个步骤一行，用例级单元格合并）。
- 本次指定的模板只用于本次；只有你明确要求“设为默认”时，才会保存为你的默认模板。
- 模板可以是 xlsx、docx、Markdown；扩展名与实际内容不符（例如 HTML 存成 .xlsx）也能识别，agent 会按实际结构决定怎么生成。

## 来源、参考与草稿导航

`cases.json` 可选记录文档级 `document.sources` 和用例级 `参考来源`。旧字符串和 `{type, ref, note}` 对象仍可用，也可以记录需求链接、章节或本地路径，参考用例的可读编号、系统ID、内容版本、索引记录链接、正文章节链接、适配理由与未确认项。信息由 agent 阅读复核后填写，脚本不推测缺失的ID、版本或地址；未知字段也会保留。

有来源时，xlsx 默认新增“来源与参考”工作表，docx/Markdown 默认追加同名小节；Word 和 Excel 中的来源、索引、正文与目录链接可点击。本地来源路径保留，系统ID作为追溯信息展示。映射可用 `sources_sheet: false` 或 `sources_section: false` 明确省略附加表或小节，报告会记录省略；未记录来源时保持原输出。格式见 [来源字段说明](../skills/lark-testcase-write/references/cases-format.md)。

上传 Markdown 草稿时可用 `--cases` 附加来源，用 `--draft-folder-url` 或 `document.navigation.draft_folder_url` 提供草稿目录链接；缺失时会明确说明，不根据 token 猜地址。草稿包含目录导航与同批附件名称。

如需给相关草稿添加反向链接，可用 `--backlink` 指定目标。目标必须同时在 `document.navigation.editable_drafts` 中声明为可编辑草稿；已知需求/参考来源和配置中的正式库资源会被拒绝。只在本次创建 Markdown 草稿时追加反链，不重试结果未知的写入。此功能不向正式库发布用例。

## 与其他 skill 的关系

- 可以单独使用，不需要先装 `lark-testcase-search` 或 `lark-testcase-maintain`。
- 需要正式入库时，把生成的用例文档交给 `lark-testcase-maintain` 按普通文档导入。

## 边界

- 覆盖率只说明 agent 给出的模型被覆盖，不代表用例已在台架或设备上执行通过。
- 生成的 xlsx 用 `openpyxl` 写出，没有在 Excel/WPS 中做公式实算和打印版式检查时会如实说明。
- 输出必须写在所有输入文件所在目录之外，不会覆盖需求、模板等来源文件。
- 来源链接结构与目标保存可用本地检查核验；目标账号的访问权限、实际点击与视觉效果仍需在使用环境验证。
